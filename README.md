# 給家人的婚禮小冊

這個儲存庫只放家庭可見的靜態網頁（GitHub Pages）。婚禮專案的完整資料、試算表、賓客名單與財務模型留在私人的 Alive 專案，不放進來。

## 頁面內容（家庭討論版 04，對應 Alive v6）

- 一眼看完：提親 → 登記 → 訂婚 → 結婚，四件事的日期、狀態與預算小計
- 每一件事：建議日期與候選日、婚顧提醒、當天行程（示意時間）、要準備的東西、這一場的預算
- 結婚一段另有「午宴／晚宴」三種迎娶排法的時間與多出費用比較，長輩可表態傾向（`phases[].compare`）
- 每個月要做什麼：2026-10 到 2027-08 的時間表，會自動標示「這個月」
- 預算總覽：依四件事、依負擔方（男方家／新人／女方家）的金額與比例
- 送出建議、已確認的事、資料來源

## 長輩怎麼提建議

長輩可以在手機上修改金額、調整負擔比例、標記「這項可以不用」、新增預算項目、補充要準備的東西、寫下建議日期。

- 修改**只存在長輩自己的瀏覽器**（localStorage），不會改到 `content.js`，也不會上傳。
- 按「用 LINE 傳給新人」或「用 Email 寄出」，會產生一段文字摘要和一個 `#p=` 連結。
- 新人點開連結就會進入「提案檢視」：頁面套用該長輩的版本，被改過的項目以底色標出，頂端有「複製提案資料」可取得 JSON。
- 採納與否由新人決定；採納的部分手動改進 `content.js`，修改 `updated`、`version`，並在 `decisions` 補一筆說明。

## 更新資料

只編輯 `content.js`：

- `phases[].budget[]`：`amount` 為目前試算、`low`／`high` 為區間、`split` 為負擔比例（合計 100）。
- `private: true`：新人自理、不在頁面列金額。`locked: true`：不可修改（例如女方主辦的訂婚宴）。
- 預算合計須與 Alive `build/Wedding_Family.md` 的「本版可見預估合計」一致（v6：1,296,400）。
- 預算項目 `id` 盡量沿用 Alive `budget.csv` 的 `Budget_ID`，方便對照。改 `id` 會讓舊的提案連結對不上該項目。

## 揭露原則

- 只放 Alive `data/` 中 Visibility = F 的內容。C／P 層級（個人資金、借款、蜜月、三姑位置、私下談話）不得出現在這裡。
- 這是公開儲存庫，GitHub Pages 網址任何人拿到都能看；`index.html` 已加 `noindex` 減少被搜尋引擎收錄，但這不是存取控制。
- 「已確認」與「建議」必須分開；收到的建議不會自動改成已確認。
- 兩家看同一份頁面，不另做男方版／女方版；大聘等金額照實寫明尚未談定的部分。

## 本機瀏覽

直接開啟 `index.html` 即可。沒有外部相依套件或追蹤碼。
